## Pre-requisites

- Your Odoo instance is accessible via mobile device
- You have an API Key configured

## Start the app

- Go to "Inventory -\> Configuration -\> Shopfloor -\> Shopfloor App"
- In the login screen fill in your API key
- Hit "Login"

## Select a profile

Several profiles can be configured in the backend, you must choose one
before starting.

- Tap on "Configure profile"
- Select a profile

This will load all available menu items for the selected profile.

## Change language

- Go to "Settings -\> Language"
- Select a language

## Customization

Please refer to shopfloor_mobile_custom_example.

## Working environment

You can control which running env is considerd by Odoo config or env
vars.

For Odoo config: running_env or shopfloor_running_env.

For env var: RUNNING_ENV or SHOPFLOOR_RUNNING_ENV.

Expected key RUNNING_ENV is compliant w/ server_environment naming but
is not depending on it.

Additionally, as specific key for Shopfloor is supported.

**You don't need \`server_environment\` module to use this feature.**

## Assets

The app does not use Odoo assets bundles: JS and CSS files are served
straight from the `static` folder of each module.

### How it works

The main template (`shopfloor_mobile_base.shopfloor_app_main`) renders an
[import map](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/script/type/importmap)
before any other script. It is generated by
`shopfloor.app._make_app_importmap` and it lists every JS file found in
the `static` folder of `shopfloor_mobile_base` and of all the installed
modules depending on it, each one mapped to a versioned URL:

``` json
{
  "imports": {
    "/shopfloor_mobile_base/static/src/main.esm.js": "/shopfloor_mobile_base/static/src/main.esm.js?v=18.0.1.4.0"
  }
}
```

The map applies to every `import`, relative (`./foo.esm.js`) or absolute
(`/other_module/static/src/foo.esm.js`), hence:

- every file is loaded from its versioned URL, without any version in
  the code;
- all the modules importing the same file get the same instance of it.

The list of files is computed once per process: files change only on
deploy. In dev mode (`--dev`) it is computed on every page load so that
new files are picked up without restarting.

### Versioning

The version appended to the URLs depends on the app's "JS version mode"
(`js_version_mode`, visible in debug mode on the app form):

- **Module version** (default): the version of the Odoo module providing
  the file, eg: `?v=18.0.1.4.0`. No file is read, and it's easy to tell
  which version of a module the device loaded. Files are downloaded again
  only when the module version changes: remember to bump the version of
  your modules when their JS changes. Override
  `shopfloor.app._get_app_js_module_version` to use another versioning
  policy (eg: a project version).
- **File content**: a hash of the content of each file, eg:
  `?v=3f9a1c0b2d4e`. A file is downloaded again as soon as it changes, no
  matter the module version. Each file is read and hashed once per worker
  process (the hash is kept until the file changes on disk).

While developing, use `?debug=assets`: Odoo then serves static files
without cache.

Import maps are supported by Chrome/Edge 89+, Firefox 108+ and Safari
16.4+. Older browsers ignore the map: modules are loaded from their
plain URL, without versioning, and overrides are not applied.

### Loading your files

Add your files by inheriting `shopfloor_mobile_base.shopfloor_app_assets`
(or `shopfloor_mobile_base.shopfloor_app_demo_assets` for demo data).

ES modules must be loaded with an inline module importing the plain URL:

``` xml
<t id="new_scenario_hook" position="before">
    <script id="script_scenario_my_scenario" type="module">
        import "/my_module/static/src/scenario/my_scenario.esm.js";
    </script>
</t>
```

Do not use `src` for ES modules: the import map does not apply to the
`src` attribute, the file would be loaded twice (once via `src`, once
via the map when imported by another module) and it would not be
versioned. Files that are only imported by other files (registries,
services, mixins, ...) do not need a tag at all.

Classic scripts and stylesheets cannot use the import map: use the
`static_url` helper to get a versioned URL:

``` xml
<link
    id="link_css_my_module"
    t-att-href="static_url('/my_module/static/src/css/main.css')"
    rel="stylesheet"
/>
```

Tags are executed in the order they appear in the template, keep the
`id` attribute on them so that other modules can hook to them.

### Replacing a JS module

Replacing the tag of a module in the template does not replace the
module: other modules keep importing the original URL. To replace a
module everywhere, override `shopfloor.app._get_app_js_overrides`:

``` python
class ShopfloorApp(models.Model):
    _inherit = "shopfloor.app"

    def _get_app_js_overrides(self):
        res = super()._get_app_js_overrides()
        res.append(
            (
                "/shopfloor_mobile_base/static/src/services/process_registry.esm.js",
                "/my_module/static/src/services/process_registry.esm.js",
            )
        )
        return res
```

Every import of the original URL now loads your file. Inside your file,
the original URL still points to the original module, so you can extend
it. Your module must export the same names:

``` javascript
import {ProcessRegistry} from "/shopfloor_mobile_base/static/src/services/process_registry.esm.js";

export class MyProcessRegistry extends ProcessRegistry {
    // ...
}

export var process_registry = new MyProcessRegistry();
// Allow further overrides to extend this one
export {MyProcessRegistry as ProcessRegistry};
```

Several modules can replace the same file: always append to the result
of `super()`. Each replacement gets the previous one when importing the
original URL (this is done with import map `scopes`).

The method is called on the app record: you can return different
overrides per app (eg: based on `self.tech_name`).
